01一页看懂

三套方案保护的位置不同，所以验证的重点也不同。

TDC 可信空间计算

CPU 机密虚机 + 加速卡独占直通

CDC 机密空间计算

CPU 机密虚机 + GPU 机密计算模式

  • CPU 内存由 Intel TDX 硬件加密
  • GPU 显存处于 CC 保护模式，GPU 身份可由 NVIDIA 官方远程证明

  • 加速卡不持有密钥，只算密态分量

02原理：三条独立的加密路线

一次矩阵乘里的 OTP 掩码

# CPU 可信环境内 xq = quantize(x) # 量化成整数 r0, r1 = fresh_random_masks() # 每次新生成的一次性掩码 c0 = (xq + r0) mod q0 # 加掩码，按两个模数拆分 c1 = (xq + r1) mod q1 send_to_accelerator(c0, c1) # 送出去的只有 c0、c1 # 加速卡上 y0 = MatMul(c0, W) mod q0 y1 = MatMul(c1, W) mod q1 # 只算密态分量 # 回到 CPU 可信环境 y = unmask(y0, y1, r0, r1) # 去掉掩码，合并得到结果 wipe(r0, r1) # 掩码用完即清零

为什么加速卡看不出原始数据

每次计算都用新生成的随机掩码，同一个输入两次送到卡上的数据完全不同。掩码只存在于 CPU 可信环境，卡上既没有掩码也没有密钥。

为什么结果不受影响

矩阵乘是线性运算，掩码带来的部分可以在 CPU 可信环境里精确扣除。实测：明文基线与密态计算结果逐字节相同。

安全口径

掩码由操作系统密码学安全随机数生成器（getrandom）产生、严格一次一密、用后清零，按计算安全表述。

常见误解：客户端做了 OTP 吗？没有。三条路线里客户端都只做传输加密。OTP 只属于 FEC 路线，是在服务器的 CPU 可信环境内部、数据送往加速卡之前才加上的。

04客户自验：你可以亲手做的验证

目标是让客户自己出题、自己验证、自己留证据，而不是只看我们给的结论截图。

客户是在验证服务器端的可信环境吗？是的。客户端在发送任何数据之前，先生成一个只有自己知道的随机数（challenge）发给服务器，服务器的可信环境用硬件密钥签出一份包含这个随机数的证明报告。客户端核对签名、设备证书和随机数都正确，才会继续建立密钥、发送数据。随机数每次不同，所以旧报告无法冒用。

客户独立完成 在客户自己的电脑上，用交付的 SDK 自验工具和通用抓包软件即可完成，不依赖我们的任何采集链路。

自己出题

你做什么写一段测试内容，在里面放一个只有你知道的随机标记，例如 CUST-7F3A9E21B4C8。
为什么标记由你决定，后面在抓包里搜它，结论才是你自己的。

先验证服务器身份（远程证明）

你做什么运行 SDK 自验工具 security_customer_selfcheck.py，它会自动生成新鲜 challenge 并核验服务器返回的证明报告。
看到什么算通过报告中 attestation_enabled、fresh_challenge、initialized 均为 true。
原理：证明报告由服务器芯片内的硬件密钥签名，包含本次 challenge。我们实测过：错误 challenge、篡改签名、缺设备证书都会被拒绝（7/7）。

发送请求，同时自己抓包

你做什么打开 Wireshark 或 tcpdump -i any port 8101 -w my.pcap，然后用 SDK 发送第 1 步的测试内容。
看到什么算通过在抓包文件中搜索你的标记和问题原文：都搜不到。
可选对照：同一内容再发一次，两次抓到的密文完全不同，说明每次加密都使用新的随机数。

核对返回结果

你做什么查看 SDK 解密后的回答，以及自验工具的事件记录。
看到什么算通过回答正常可读；流式返回的每一段都经过认证解密（four_authenticated_deltas: true），并正常结束（done: true）。
原理：每段返回都带认证标签，途中被改动一个字节，客户端就会解密失败，而不会得到被篡改的结果。

确认密钥已清理，保存证据

你做什么保存自验工具输出的 JSON 报告和你的抓包文件，用 sha256sum 记录摘要。
看到什么算通过报告 10 项检查全部通过，其中 test_dek_removed: true 表示本次测试使用的数据密钥已删除。
SDK 文件（client.py、crypto_utils.py 等）随交付清单附 SHA-256，客户可先核对自己拿到的 SDK 与交付版本一致。

CDC 客户可额外做：GPU 远程证明

在机密虚机内运行 cdc_attest.py，向 NVIDIA 官方证明服务 NRAS 发起证明。返回的 EAT token 由 NVIDIA 签名，客户可以用 NVIDIA 公开的证书独立验签，不需要信任我们。

x-nvidia-overall-att-result : true x-nvidia-gpu-attestation-report-signature-verified: true x-nvidia-gpu-attestation-report-cert-chain-validated: true x-nvidia-gpu-attestation-report-nonce-match : true x-nvidia-gpu-driver-rim-signature-verified : true x-nvidia-gpu-vbios-rim-signature-verified : true x-nvidia-gpu-driver-version : 610.57.04 x-nvidia-gpu-vbios-version : 97.00.D9.00.35

每一行的含义

签名、证书链通过：这份报告确实出自一块真实的 NVIDIA GPU。

nonce 匹配：报告是针对这一次请求新生成的，不是旧报告重放。

驱动与 VBIOS 度量签名通过：GPU 上运行的是正版、未被篡改的驱动和固件。

05参考 Tinfoil 的客户验证思路

Tinfoil 是一个机密计算 AI 推理服务，特点是客户端开源、每次连接都由客户端自动验证服务端的硬件证明。它的核心思路是：验证在客户手里完成，而不是由服务方出具结论。我们的自验设计借鉴了这一点。

Tinfoil 的做法作用我们的对应做法
