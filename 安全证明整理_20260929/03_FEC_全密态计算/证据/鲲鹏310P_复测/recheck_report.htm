三、复测查出的问题

首轮报告有一处说法与证据不符：宿主 npu-smi 首轮报告写"宿主未装 npu-smi、无法查询"。但首轮证据里那一段是空的——按探针脚本的逻辑，空输出恰恰说明 command -v npu-smi 成功了（否则会打印 "not installed"）。

查实结果：宿主装有 npu-smi（/usr/local/sbin/npu-smi，/usr/local/Ascend 也在），执行时挂起并被 timeout 杀掉（退出码 124），输出停在缓冲区里丢失，所以两轮都显示为空。

安全结论不变：宿主依然访问不到加速卡。而且"工具装着也用不了"比"没装"更有说服力——因为两张卡已被 vfio-pci 绑给虚机独占。
已处理：探针改为先落盘再读、显式记录安装路径与退出码；判据由"宿主未装 npu-smi"改为"宿主无法通过 npu-smi 访问设备"；相关报告表述需同步更正。
两处需要说明的差异（均非回归） 一、故障注入的偏差数值不同。批次静默缺口那条，首轮偏差 567.615、复测 564.015。这是预期内的——篡改造成的误差与每轮随机生成的 OTP 掩码相关，量级重现即可，不该逐位相同。对比比的是判据与计数，不比这个数值。

二、编排器首跑两项失败。firmware 与 live 用 --output 写单个文件，而编排器没为它们建父目录。属编排器缺陷，已修并补跑，与被测系统无关。

五、复测怎么跑的

全部实验由一个编排器驱动，参数与首轮完全一致（从首轮的原始命令记录中还原）：

python scripts/security_rerun_all.py --output-dir results/security_recheck_20260918

python scripts/security_compare_batches.py \
    --baseline results/security_full_20260918 \
    --recheck  results/security_recheck_20260918 \
    --output   results/security_recheck_20260918/comparison.json

编排器内置三条生产保护：碰设备的实验执行前检查后端是否空闲，非空闲则跳过而不是硬跑；不在生产源码树内编译；不用非法指针启动 kernel。每项记录执行前后的后端请求数与空闲状态。

本轮同时完成的代码整理 把原先散在临时 shell 里的两项探针正式化，并新增编排与对比工具：
  • security_cdc_platform_check.py —— CDC 平台能力核查（原为临时 shell）
  • security_tdc_access_check.py —— TDC-04 非授权侧访问（原为临时 shell）
  • security_rerun_all.py —— 全量复测编排器
  • security_compare_batches.py —— 两轮结果逐项对比
  • README_SECURITY.md —— 脚本说明，63 个文件分为现役 31 / 历史 36
