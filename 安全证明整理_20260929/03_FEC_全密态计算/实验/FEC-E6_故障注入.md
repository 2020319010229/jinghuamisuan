# FEC-E6 故障注入

| 项目 | 内容 |
| --- | --- |
| 对应条目 | FEC-08 异常时的安全处理（昇腾 310P） |
| 地点 | 鲲鹏 virtCCA CVM，独立进程（引擎源码复制出生产目录；设备权重篡改测试后恢复） |
| 时间 | 首轮 2026-09-16（fault_injection_02），复测 2026-09-18 |
| 结果 | 10/10 用例符合预期；机密性边界保持，记录 1 项完整性风险 |

## 目的

在异常条件下，确认引擎会中止任务，不会退回到无掩码的明文计算。

## 方法

用 `security_fault_injection.c` 构造形状非法、不支持的切分、设备结果被篡改等情况；用 `security_fault_getrandom.c` 让 `getrandom` 强制失败，模拟随机源失效。每个用例记录返回码，并与 CPU 参考结果比对。

## 结果

| 用例 | 预期 | 观测 |
| --- | --- | --- |
| baseline_M1 | 正常且与 CPU 参考一致 | rc=0，最大偏差 2.98e-05 |
| baseline_M4 | 同上 | rc=0，最大偏差 2.98e-05 |
| K 不是 32 的倍数 | 中止 | rc=-1 |
| N 不是 16 的倍数 | 中止 | rc=-1 |
| 不支持的切分 | 中止 | rc=-1 |
| **随机源失效** | **中止，不做无掩码计算** | **rc=-1** |
| 随机源恢复后 | 恢复正常 | rc=0，偏差 2.98e-05 |
| 设备结果被篡改 · 单行 M=1 | 在 CPU 侧检出并纠正 | rc=0，纠正回 CPU 值 |
| 设备结果被篡改 · 批次 M=4 | 复现：批次路径不做交叉校验 | rc=0，偏差 564.015，错误结果按成功返回 |
| 恢复设备权重后 M=4 | 结果恢复一致 | rc=0，偏差 2.98e-05 |

## 说明

- **机密性**：所有异常路径下，卡上都只有密文分量；随机源失效时直接中止。
- **完整性风险**：批次路径（M>1）不校验设备返回结果（`verify` 只在 M==1 开启），被控制或故障的加速卡可以在批次推理中静默改结果。这不影响数据保密，但影响结果可信度。源码注释显示这是有意的性能取舍。
