# 方案三：全密态计算（FEC）

> 架构：CPU-TEE + 通用加速卡（本次为昇腾 310P）
> 核心主张：数据在离开 CPU-TEE 前完成 OTP 密态转换；加速卡接收、计算、返回的都是密态数据；密钥不出 CPU-TEE。
> 边界：随机源是操作系统 CSPRNG（getrandom），不是物理真随机源，所以全部结论按**计算安全**口径陈述，不写“信息论安全”。

## 1. 在哪里做的

| 项 | 内容 |
| --- | --- |
| 平台 | 鲲鹏 920 宿主 + virtCCA 机密虚机（192 vCPU / 129 GiB，内核 6.6.0-98.0.0.103.oe2403sp2） |
| 加速卡 | 2 × Ascend 310P（44 GiB），TP=2 / MoE 专家并行 |
| 引擎 | C/CANN OTP RNS 引擎，运行模式 `shannon_rns_otp`，连续批处理 |
| 模型 | qwen3.5-35b-a3b-otp-c（W8A8） |
| 入口 | 网关 :8000（加密入口 + 明文对照入口）、SDK :8101 |
| 时间 | 首轮 2026-09-16 ~ 09-17，全量复测 2026-09-18（本目录证据取自复测） |

## 2. 数据怎么走

```
客户端 ──(X25519 协商 + AES-GCM 加密)──▶ CVM（CPU-TEE）
                                         ├ 解密、分词、embedding
                                         ├ 线性层输入：量化 → 加 OTP 掩码 → 按 RNS 模 q0/q1 拆分量 ──▶ 310P 只算密文分量的矩阵乘
                                         ├ ◀── 返回密文分量结果
                                         ├ 去掩码、归一化、激活、softmax、采样（都在 CVM 内）
客户端 ◀──(加密的流式 delta)──────────────┘
```

## 4. 本方向结论

| 计划书条目 | 判定 | 依据 |
| --- | --- | --- |
| FEC-01 CPU-TEE 可信状态与处理边界 | 通过 | 证明负例 7/7（见 [TDC-E1](../01_TDC_可信空间计算/实验/TDC-E1_机密虚机状态与远程证明负例.md)）；解密、分词、非线性、解盲、采样在 CVM 内 |
| FEC-02 OTP 密钥全生命周期 | 通过（计算安全口径） | E2：4096 个掩码全部唯一，两个 RNS 模域各 1,048,576 样本方差比 0.999964 / 1.001224，zeroize=PASS；E7：日志与临时文件无明文 |
| FEC-03 客户端密态转换展示 | 通过（SDK） | E8：客户视角独立执行 10/10 |
| FEC-04 网络传输密态验证 | 通过 | E1：两入口双点抓包，植入标记不可见，阳性对照可见 |
| FEC-05 CPU—加速卡接口密态 | 通过（软件接口口径） | E3：96 个独立合成算例，关闭 CPU 补正，D2H 原始整数分量与参考一致 |
| FEC-06 密态计算正确性 | 通过 | E4：明文入口与密文入口 3 轮输出逐字节相同；E3 算子级零差异 |
| FEC-07 线性与非线性边界 | 通过 | E5：7 种降级字段无效，模式恒为 `shannon_rns_otp`；掩码开关只能由启动命令行设置 |
| FEC-08 异常时的安全处理（昇腾 310P） | 通过 | E6：非法形参、不支持的配置、随机源失效时全部中止（rc=-1），不会在无掩码状态下继续计算 |
