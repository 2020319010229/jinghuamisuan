# TDC-E2 宿主反向读取 CVM 内存

| 项目 | 内容 |
| --- | --- |
| 对应条目 | TDC-03 CPU 内存加密与地址空间隔离 |
| 地点 | 鲲鹏 virtCCA 宿主机（以 root 身份读取 qemu 进程内存） |
| 时间 | 全量扫描 2026-09-16（tdc_memory_06_full），复测 2026-09-18 |
| 结果 | 通过：读取 130.39 / 134.19 GB（97.16%），CVM 内运行时植入标记 0 命中 |

## 目的

模拟拥有 root 权限的宿主管理员，直接读取机密虚机的内存，看能否取到虚机里的业务明文。

## 方法

采用“植入标记 + 阳性对照”方法：

1. 在 CVM 内启动一个进程，把随机生成的标记字符串常驻内存（**被测对象**）。
2. 在宿主机上启动一个普通进程，持有另一个随机标记（**阳性对照**，扫描器必须能搜到它，否则扫描方法无效）。
3. 在 CVM 内部先自扫一遍，确认标记确实驻留（**有效性前提**）。
4. 宿主以 root 读取 `/proc/<qemu_pid>/mem`，在 guest 内存映射中逐段检索标记。
5. 另在 CVM 内写入一个磁盘标记，检查磁盘 I/O 路径是否在宿主侧留下明文。

## 过程

- 脚本：`security_tdc_memory_isolation.py`
- 首轮 01–05 为方法调试（覆盖率 35%–42%，逐步修正读取方式）；06_full 为全量扫描；复测沿用 06 的方法。

## 结果

| 段 | 已读取 | 运行时植入标记 | 静态结构明文 |
| --- | --- | --- | --- |
| 段 1 | 44.0 GB | 0 | 245 处 |
| 段 2 | 44.0 GB | 0 | 0 |
| 段 3 | 42.4 GB | 0 | 0 |
| 合计 | 130.39 GB（97.16%，全程无 errno） | **0** | 245 |

| 对照 / 附加检查 | 结果 |
| --- | --- |
| 宿主阳性对照 | 命中（扫描方法有效） |
| CVM 内自扫 | 命中（标记确实驻留） |
| 磁盘 I/O 标记 | 宿主侧 0 命中 |
| 复测（2026-09-18） | 覆盖 97.12%，植入标记 0 命中，结论一致 |

## 说明

- 结论为“宿主读不到 CVM 运行时的业务数据”。段 1 有 245 处静态结构明文（`guest_no_structural_plaintext=false`），来源未定位，因此**不表述为“CVM 内存对宿主完全不可见”**。
- 段 2、3 共 86 GB 连 ELF 头都没有；这台 CVM 正运行 35B 模型、占用 40 GB 以上内存，如果内存对宿主明文可见，不会是这种结果。
