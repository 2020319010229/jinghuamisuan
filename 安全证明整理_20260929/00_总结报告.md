# 荆华密算三类密态计算方案安全证明 · 总结报告

> 对应文件：《荆华密算三类密态计算解决方案安全证明任务计划书》
> 整理日期：2026-09-29
> 实验时间：2026-09-16 ~ 2026-09-24
> 性质：针对实际部署状态的工程安全验证，不等同于形式化密码学证明或权威认证。所有结论只适用于下文列出的硬件、固件、驱动和版本。

## 一、结论

| 方案 | 验证平台 | 结论 |
| --- | --- | --- |
| **TDC 可信空间计算** | 鲲鹏 920 virtCCA 机密虚机 + 2 × 昇腾 310P 直通；海光 C86 Guest（数据路径补充） | 机密虚机状态、远程证明负例、宿主反向读内存、加速卡独占直通、设备残留、数据路径均实测通过。 |
| **CDC 机密空间计算** | Intel TDX 机密虚机 + NVIDIA B200（CC 模式）直通 | CPU（TDX）与 GPU（CC，PRODUCTION）同时处于机密计算状态；GPU 远程证明通过 NVIDIA NRAS；宿主以 root 扫描 16.66 GB 内存，纯内存 canary 0 命中。 |
| **FEC 全密态计算** | 鲲鹏 920 virtCCA + 2 × 昇腾 310P，Qwen3.5-35B-A3B | 网络只见密文，加速卡只见密态分量，密钥不出 CPU-TEE，解密结果与明文逐字节一致，异常时中止而不回退明文。按计算安全口径成立。 |

三套方案各自独立取证，没有用一套方案的证据替代另一套。

## 三、公共任务

### G-01 安全主张与威胁模型

| 角色 | 信任关系 |
| --- | --- |
| 宿主管理员（含 root） | 不可信。TDC-E2、CDC-E3 专门以 root 身份反向读内存 |
| 网络监听者 | 不可信。FEC-E1 在宿主与 CVM 两点抓包 |
| 加速卡侧 | TDC：卡上是明文，依靠独占直通隔离；CDC：GPU 处于 CC 模式，受硬件保护；FEC：不可信，卡上只有密态分量，不持有密钥 |
| CPU 机密域内部 | 可信。解密、分词、非线性计算、解盲都在其中以明文进行 |

### G-02 环境与版本基线

见第二节。鲲鹏平台的基线由 `env_baseline.json`、`firmware.json`、`live_status.json` 固化，并核对了**运行进程**的二进制摘要（`/proc/<pid>/exe` = `e015292c…`），不只是磁盘文件。海光与 B200 的基线分别见 `env_facts.json`、`host_evidence.txt` / `cvm_evidence.txt`。

### G-03 客户端验证工具（SDK）

客户自验工具 `security_customer_selfcheck.py` 在宿主机以客户视角独立执行，10/10 通过：远程证明启用、新鲜 challenge、4 个经认证解密的 delta、测试 DEK 删除等。SDK 全流程记录 21 个事件（身份验证 → prompt 加密 → 提交 → 加密 delta 接收与解密 → 结束），不保存 DEK 或明文。→ [FEC-E8](03_FEC_全密态计算/实验/FEC-E8_客户自验与SDK全流程.md)

### G-04 网络传输安全

| 入口 | 抓包位置 | 检查项 | 结果 |
| --- | --- | --- | --- |
| 网关 :8000 | 宿主 + CVM | 23 | 23/23：prompt 标记不可见，阳性对照可见，两处流一致 |
| SDK :8101 | 宿主 + CVM | 11 | 11/11 |

异常连接阻断：远程证明负例 7/7（错误 challenge、错误度量、签名篡改、缺设备证书）；协议负例全部拒绝（密文篡改、AAD 降级、非法 nonce、非法公钥、重放）。→ [FEC-E1](03_FEC_全密态计算/实验/FEC-E1_网络抓包_网关与SDK.md)、[FEC-E2](03_FEC_全密态计算/实验/FEC-E2_协议与密钥安全验收.md)、[TDC-E1](01_TDC_可信空间计算/实验/TDC-E1_机密虚机状态与远程证明负例.md)

## 五、方案二 CDC

| 条目 | 判定 | 实验与关键数据 |
| --- | --- | --- |
| CDC-01 GPU-CC 正式模式 | 通过 | [CDC-E1](02_CDC_机密空间计算/实验/CDC-E1_CPU与GPU双TEE状态核验.md)：CVM 内 `CC State: ON`、`CC Environment: PRODUCTION`、`Ready`；宿主同一时刻 `CC State: OFF`。前置核查 [CDC-E0](02_CDC_机密空间计算/实验/CDC-E0_昇腾310P机密计算能力核查.md) 确认昇腾 310P 不具备 GPU-CC，因此选用 B200 |
| CDC-02 CPU-TEE 可信状态 | 通过（状态） | CDC-E1：`tdx: Guest detected`、`Memory Encryption Features active: Intel TDX`；`/dev/tdx_guest` 与 configfs-tsm 可用 |
| CDC-03 GPU 远程证明 | 通过 | [CDC-E2](02_CDC_机密空间计算/实验/CDC-E2_GPU远程证明NRAS.md)：NVIDIA NRAS 返回总体结果 true，报告签名、证书链、nonce、驱动 RIM、VBIOS RIM 均为 true |
| CDC-05 内存与显存隔离 | 通过 | [CDC-E3](02_CDC_机密空间计算/实验/CDC-E3_宿主内存取证_双canary.md)：纯内存 canary Guest 内 24,102 份，宿主 root 扫 QEMU 16,659.8 MB **0 命中**（阳性对照 24,105）；显存 Protected 185,970,368 KiB / Unprotected 0 |

CDC 需要一起说明的边界：Guest 主动写入模拟设备（磁盘、网络）的数据经共享 DMA 页，宿主可见。实验一中命中的 7 次正是 `sudo` 审计日志经 virtio-blk 留下的足迹，已定位。这类数据需要传输层加密保护。

## 六、方案三 FEC

| 条目 | 判定 | 实验与关键数据 |
| --- | --- | --- |
| FEC-01 CPU-TEE 状态与处理边界 | 通过 | 证明负例 7/7；解密、分词、embedding、归一化、激活、softmax、解盲、采样都在 CVM 内 |
| FEC-02 OTP 密钥全生命周期 | 通过（计算安全） | [FEC-E2](03_FEC_全密态计算/实验/FEC-E2_协议与密钥安全验收.md)：4096 个掩码全部唯一；两个 RNS 模域各 1,048,576 样本，方差比 0.999964 / 1.001224；zeroize=PASS；私钥文件 0600。[FEC-E7](03_FEC_全密态计算/实验/FEC-E7_日志与临时文件残留.md)：日志、临时文件、容器日志无标记 |
| FEC-03 客户端密态转换展示 | 通过（SDK） | FEC-E8：客户自验 10/10 |
| FEC-04 网络传输密态 | 通过 | FEC-E1：23/23、11/11；4096 次请求 nonce 与密文唯一 |
| FEC-05 CPU—加速卡接口密态 | 通过 | [FEC-E3](03_FEC_全密态计算/实验/FEC-E3_加速卡接口密态验证.md)：96 个独立合成算例，关闭 CPU 补正，D2H 原始整数分量与参考 0 差异；同一输入重复发送 H2D 指纹不同 |
| FEC-06 密态计算正确性 | 通过 | [FEC-E4](03_FEC_全密态计算/实验/FEC-E4_明文与密文双入口一致性.md)：明文入口与密文入口 3 轮输出 SHA-256 **逐轮完全相同** |
| FEC-07 线性 / 非线性边界、无明文旁路 | 通过 | [FEC-E5](03_FEC_全密态计算/实验/FEC-E5_降级字段与明文回退.md)：7 种降级字段全部无效，模式恒为 `shannon_rns_otp`；掩码开关只能由启动命令行设置 |
| FEC-08 异常时安全处理（昇腾 310P） | 通过 | [FEC-E6](03_FEC_全密态计算/实验/FEC-E6_故障注入.md)：非法形参、不支持的切分、随机源失效均中止（rc=-1），不会在无掩码状态下继续计算 |

OTP 前提逐条对照：密钥长度满足、严格一次一密（4096 唯一）、保密存储（0600，宿主读内存 0 命中）、安全销毁（zeroize=PASS）四条满足；“密钥真随机”一条使用 OS CSPRNG 而非物理真随机源，因此按**计算安全**表述。
